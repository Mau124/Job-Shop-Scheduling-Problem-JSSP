The project is asking you to solve the same scheduling problem using **four different AI/optimization strategies** and then compare them fairly. Here’s what each concept means.

1. **What is JSP?**  
   **JSP = Job-Shop Scheduling Problem**. You have several **jobs**, and each job consists of a sequence of **operations**. Every operation must run on a particular **machine** for a specified amount of time.

   For example:

   ```text
   Job 0:
       Operation 0 → Machine 0 for 3 minutes
       Operation 1 → Machine 2 for 5 minutes
       Operation 2 → Machine 1 for 2 minutes

   Job 1:
       Operation 0 → Machine 1 for 4 minutes
       Operation 1 → Machine 0 for 2 minutes
       Operation 2 → Machine 2 for 3 minutes
   ```

   The operations of a job must happen in order, and two operations cannot use the same machine simultaneously. Your goal is to determine **when every operation starts** so that all jobs finish as early as possible. This is the standard formulation used by optimization tools such as Google OR-Tools. [Google for Developers](https://developers.google.com/optimization/scheduling/job_shop)

2. **Why is it a complex problem?**  
   JSP is difficult because there are an enormous number of possible schedules. Every time several jobs need the same machine, you must decide which one goes first. That decision can affect later machines because each job also has precedence constraints.

   Imagine 10 jobs competing for 10 machines. A decision like:

   ```text
   Machine 3:
   Job 2 → Job 7 → Job 1 → Job 8 → ...
   ```

   is only one possible ordering. Change that order and the final completion time can change dramatically.

   The general JSP is **NP-hard**, meaning there is no known algorithm that can efficiently find the optimal solution for every large instance. [Cornell Optimization Wiki](https://optimization.cbe.cornell.edu/index.php?title=Job_shop_scheduling\&utm_source=chatgpt.com) This is exactly why your professor wants you to compare DFS/IDS, A*, local search, and CSP: they explore this huge search space in very different ways.

3. **How is a JSP problem defined?**  
   Formally, you define a set of jobs \(J\) and machines \(M\). Job \(j\) contains an ordered sequence of operations:

   \[
   O_{j,1},O_{j,2},...,O_{j,k}
   \]

   Each operation contains two important pieces of information:

   \[
   O_{j,k}=(machine,\ processing\ time)
   \]

   So an instance might simply be represented in Python as:

   ```python
   jobs = [
       [(0, 3), (1, 2), (2, 2)],
       [(0, 2), (2, 1), (1, 4)],
       [(1, 4), (2, 3)]
   ]
   ```

   Here `(0, 3)` means **use machine 0 for 3 time units**.

   If \(S_{j,k}\) is the starting time of operation \(k\), the precedence constraint is essentially:

   \[
   S_{j,k+1} \geq S_{j,k}+p_{j,k}
   \]

   where \(p\) is the operation duration. You also need a constraint saying operations assigned to the same machine cannot overlap. OR-Tools uses essentially this same model with start variables, end variables, interval variables, precedence constraints, and `NoOverlap` machine constraints. [Google for Developers](https://developers.google.com/optimization/scheduling/job_shop)

4. **What is an instance?**  
   An **instance** is simply **one specific JSP input/problem**.

   Think of JSP as the game and an instance as one particular level of the game.

   For example:

   ```text
   3 jobs
   3 machines

   J0: (M0,3) (M1,2) (M2,2)
   J1: (M0,2) (M2,1) (M1,4)
   J2: (M1,4) (M2,3)
   ```

   That's one instance.

   `ft10`, `la01`, `abz5`, and `ta01` are names of famous benchmark instances. JSPLIB, for example, contains families including FT, LA, ABZ, ORB, SWV, YN and Taillard instances. [GitHub](https://github.com/tamy0612/JSPLIB)

5. **What is makespan?**  
   **Makespan** is the total time required until **all jobs have finished**. It is normally written:

   \[
   C_{\max}
   \]

   Suppose your schedule finishes the jobs at these times:

   ```text
   Job 0 finishes at 18
   Job 1 finishes at 22
   Job 2 finishes at 17
   Job 3 finishes at 20
   ```

   Then:

   \[
   C_{\max}=\max(18,22,17,20)=22
   \]

   So the makespan is **22**.

   Your optimization objective is therefore:

   \[
   \boxed{\min C_{\max}}
   \]

   A schedule with makespan 95 is better than one with makespan 103. Google describes the JSP objective in exactly this way: minimize the length of the schedule, measured by the latest job completion time. [Google for Developers](https://developers.google.com/optimization/scheduling/job_shop)

7. **What is an ablation study?**  
   An **ablation study** means deliberately removing or changing one component of your algorithm to measure how important that component is.

   Suppose your A* implementation has two heuristics. Instead of reporting only your best algorithm, you test:

   ```text
   A* + H1
   A* + H2
   ```

   Then compare:

   ```text
   makespan
   runtime
   nodes expanded
   maximum frontier
   ```

   If H2 expands 5,000 nodes while H1 expands 80,000, you have experimental evidence that H2 is more informative.

   Your assignment explicitly wants this idea applied to multiple algorithms: for A*, compare H1 vs H2; for CSP, compare MRV/LCV vs naive ordering; and for local search, compare neighborhoods or restarts.

   The key idea is:

   **A normal experiment asks "How good is my algorithm?" An ablation asks "Which part of my algorithm is responsible for it being good?"**

8. **Elaborate on the CSP approach with backtracking using MRV and LCV**  
   **CSP = Constraint Satisfaction Problem**. Instead of primarily thinking of JSP as moving through states, you represent it using **variables, domains, and constraints**.

   For example, you could define one start-time variable per operation:

   ```text
   S_0_0 = starting time of Job 0 Operation 0
   S_0_1 = starting time of Job 0 Operation 1
   S_1_0 = starting time of Job 1 Operation 0
   ...
   ```

   Their domains might initially be:

   ```text
   S_0_0 ∈ {0,1,2,...,H}
   ```

   where `H` is a safe upper bound on the schedule length.

   Then add constraints such as:

   ```text
   precedence:
   S_0_1 >= S_0_0 + duration_0_0

   machine conflict:
   Operation A must finish before B
   OR
   Operation B must finish before A
   ```

   **Backtracking** means you assign variables recursively. If an assignment makes the remaining problem impossible, you undo it and try another value:

   ```text
   choose variable
       ↓
   try value
       ↓
   constraints still valid?
      /       \
    yes       no
     ↓         ↓
   continue   backtrack
   ```

   **MRV = Minimum Remaining Values.** Instead of arbitrarily choosing the next variable, choose the unassigned variable with the **fewest currently legal values**. For example:

   ```text
   A domain = {2, 3, 4, 5, 6}
   B domain = {7, 8}
   C domain = {1, 2, 3, 4}
   ```

   MRV chooses **B**, because it has only two possibilities. The idea is to detect failure early rather than wasting time exploring a huge branch.

   **LCV = Least Constraining Value.** After MRV chooses a variable, LCV decides **which value to try first**. It chooses the value that eliminates the fewest possibilities from neighboring variables.

   So:

   ```text
   MRV = which VARIABLE should I assign next?
   LCV = which VALUE should I try first?
   ```

   **Forward checking** goes one step further. Every time you make an assignment, you immediately remove incompatible values from the domains of other variables. If one variable reaches an empty domain, you backtrack immediately.

   A good conceptual CSP solver for your project therefore looks like:

   ```python
   backtrack(assignment):
       if complete:
           return solution

       variable = choose_variable_MRV()

       for value in order_values_LCV(variable):
           if consistent(variable, value):
               assign(variable, value)

               forward_check()

               result = backtrack(assignment)

               if result:
                   return result

               undo_assignment()
               restore_domains()
   ```

   Libraries such as `python-constraint` provide backtracking and forward checking; its recursive solver also documents use of MRV. [Python Constraint](https://python-constraint.github.io/python-constraint/reference.html) However, because your coursework **explicitly requires MRV and LCV plus an ablation**, writing this selection logic yourself is probably the safest way to demonstrate that you actually implemented and understand it.
